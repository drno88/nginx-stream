# nginx-stream

Прокладка (TCP/UDP-прокси) на nginx: принимает соединения на этом сервере и передаёт их на другой сервер как
есть, ничего не расшифровывая. Ставится одной командой, установщик сам задаёт вопросы и всё настраивает.

```
  клиент  ──►  прокладка (этот сервер)  ──►  сервер назначения
               192.0.2.10:443                [2001:db8::10]:443
```

Клиенты подключаются к прокладке, а прокладка — к серверу назначения. Для клиента это выглядит так, будто
прокладка и есть сервер.

## Когда пригодится

- **Сервер доступен только по IPv6**, а клиенты ходят по IPv4. Прокладка принимает по IPv4 и передаёт по IPv6.
- **До сервера нельзя достучаться напрямую**, а до прокладки можно.
- **Несколько серверов за одним адресом:** порт 443 — на один сервер, 2222 — на другой и так далее.
- **Несколько сайтов на одном порту 443:** прокладка смотрит, к какому имени обращается клиент (например,
  `a.example.com` или `b.example.com`), и отправляет на нужный сервер.

Прокладке не нужны сертификаты и ключи: зашифрованные данные проходят через неё, не расшифровываясь. Чужие
настройки на сервере установщик не ломает: не удаляет пакеты, не выключает IPv6, не трогает правила фаервола,
которые были до него.

## Что понадобится

- Сервер с **Debian 12 и новее** или **Ubuntu 22.04 и новее**, доступ под `root`. Хватает 1 ядра и 512 МБ памяти.
- **Адрес сервера назначения** — куда на самом деле должны попадать клиенты: IPv4 (`203.0.113.10`), IPv6
  (`2001:db8::10`) или домен (`backend.example.com`).
- **Порты** — какие порты принимать и на какие отправлять. Если не знаете, начните с `tcp:443`.
- Если сервер назначения доступен по IPv6, у прокладки тоже должен быть IPv6. Проверить:
  `ip -6 addr show scope global` — если команда ничего не вывела, IPv6 нет, и установщик остановится с объяснением.

## Установка

1. Подключитесь к серверу по SSH под `root`.
2. Выполните команду:

   ```bash
   bash <(wget -qO- --inet4-only https://raw.githubusercontent.com/drno88/nginx-stream/main/install.sh)
   ```

   Если `wget` нет — то же через `curl`:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/drno88/nginx-stream/main/install.sh -o install.sh
   bash install.sh
   ```

3. Ответьте на вопросы (ниже — что значит каждый). Если не уверены, нажмите Enter: подставится значение по
   умолчанию, оно подходит большинству.
4. Проверьте сводку и подтвердите. Через минуту прокладка работает, а установщик печатает, какие порты она слушает.

После установки на сервере появляется команда `nginx-stream`: ею же меняют настройки, смотрят состояние и
удаляют прокладку (см. «Управление»).

## Вопросы установщика

Каждый вопрос можно задать заранее флагом — тогда установщик его не спросит (см. «Все параметры»).

**Язык** — русский или английский. По умолчанию русский.

**Адрес сервера назначения** — куда отправлять соединения: IPv4, IPv6 или домен. Это сервер, который
на самом деле обслуживает клиентов. Обязателен. Если указать домен, nginx узнаёт его IP один раз при запуске;
сменился IP у домена — перезапустите nginx: `systemctl restart nginx`.

**Правила портов** — что принимать и куда отправлять. По умолчанию `tcp:443`: принимать TCP на порту 443 и
отправлять на тот же порт сервера назначения. Как написать своё — в разделе «Правила портов» ниже.

**На каких адресах слушать?** — на каких адресах прокладки принимать соединения: только IPv4 или IPv4 и IPv6. По умолчанию — оба,
если у сервера есть IPv6. Не знаете — оставьте как есть.

**PROXY protocol** — передавать ли серверу назначения настоящий адрес клиента. Без него сервер назначения
видит адрес прокладки. По умолчанию **нет**. Включайте, только если сервер назначения настроен его принимать,
иначе ни одно соединение не пройдёт. Работает только для TCP.

**Журнал nginx** — `нет` (по умолчанию) или `только ошибки`. Ошибки полезны, если что-то не работает; журнал
лежит в `/var/log/nginx/error.log`.

**Параметры ядра** — настроить сеть под прокси: больше одновременных соединений, буферы, алгоритм BBR.
По умолчанию **да**. Настройки, которые на этом сервере нельзя поменять, просто пропускаются.

**Защита SSH от перебора** — не больше 10 новых SSH-подключений в минуту с одной сети (/24, для IPv6 — /64), лишние отбрасываются.
Подбирать пароль становится бесполезно. По умолчанию **да**. Обычной работы по SSH это не мешает.

**Защита от сканирования** — сервер перестаёт отвечать на ping и на закрытые порты, и снаружи труднее понять,
что на нём работает. По умолчанию **нет**. Если потом запустите на сервере новую службу на порту ниже 10000,
запустите `nginx-stream` и перенастройте с теми же ответами, иначе клиенты этой службы будут ждать при ошибках.

**Автообновления безопасности** — сервер сам ставит обновления безопасности (без перезагрузки). По умолчанию **да**.

**Продолжить?** — установщик показывает сводку ответов. `y` — установить, `n` — выйти, ничего не меняя.

## Правила портов

Правило — это одна запись «что принимать → куда отправлять». Несколько правил пишутся через запятую, без пробелов.

### Начнём с простого

| Запись | Что делает |
|---|---|
| `tcp:443` | принимать TCP на порту 443 → отправлять на порт 443 сервера назначения |
| `udp:443` | то же для UDP |
| `both:443` | и TCP, и UDP на порту 443 |
| `tcp:8443>443` | принимать на 8443 → отправлять на 443 |
| `tcp:2222>203.0.113.20:22` | принимать на 2222 → отправлять на **другой** сервер, `203.0.113.20`, порт 22 |
| `udp:51820>[2001:db8::20]:51820` | отправлять на сервер с адресом IPv6 — адрес пишется **в квадратных скобках** |
| `tcp:443,udp:443,tcp:2222>203.0.113.20:22` | три правила сразу |

Части записи:

- **`tcp`, `udp` или `both`** — протокол. Какой нужен, написано в настройках программы, ради которой ставится
  прокладка. Не знаете — чаще всего это `tcp`; `both` — если нужны оба.
- **порт после двоеточия** — порт, который прокладка принимает. От 1 до 65535.
- **`>` и дальше** — куда отправлять. Только порт (`>443`) — на сервер назначения из вопроса «Адрес сервера
  назначения». Адрес и порт (`>203.0.113.20:22`) — на этот сервер. Без `>` — на сервер назначения, тот же порт.

### Если нужно сложнее

Эти части нужны редко. Если не понимаете, зачем они вам, — не используйте.

| Хочу | Запись |
|---|---|
| У прокладки два внешних адреса, и с каждого — на свой сервер | `udp:192.0.2.20:443>[2001:db8::20]:443,udp:192.0.2.21:443>[2001:db8::21]:443` |
| Слушать только на одном адресе прокладки | `tcp:[2001:db8::1]:443>203.0.113.10:443` |
| Сервер назначения пускает только с определённого адреса прокладки | `udp:443>[2001:db8::21]:443@[2001:db8::5]` |
| Один порт 443, сервер выбирается по имени сайта | `tcp:443/a.example.com>203.0.113.5:443,tcp:443/*.b.example.com>203.0.113.6:443,tcp:443>203.0.113.9:443` |

- **Адрес слушания** (`192.0.2.20:` перед портом) — на каком адресе прокладки принимать это правило. Нужен,
  только если у сервера несколько внешних адресов. Адрес должен быть на сервере (`ip addr`).
- **Исходящий адрес** (`@адрес` в конце) — с какого адреса прокладки идти к серверу назначения. Нужен, когда
  у прокладки несколько адресов, а сервер назначения пускает только с одного. Адрес должен быть на сервере и
  того же типа, что адрес назначения: IPv4 с IPv4, IPv6 с IPv6.
- **Имя** (`/a.example.com` после порта) — только TCP. Прокладка смотрит, к какому имени обращается клиент
  по TLS (HTTPS и другие шифрованные протоколы), и отправляет на сервер этого правила. Имя пишется точно
  (`a.example.com`) или для всех поддоменов (`*.b.example.com` — подходит `x.b.example.com`, но не сам
  `b.example.com`). Правило на тот же порт без имени — «по умолчанию»: туда идут все остальные, в том числе
  без TLS. Имена должны указывать в DNS на адрес прокладки. Для UDP на том же порту — отдельное правило `udp:443`.

Полный формат одного правила:

```
протокол:[адрес_слушания:]порт[/имя][>[хост:]порт_назначения][@исходящий_адрес]
```

### Когда установщик откажет

Установщик проверяет правила до установки и объясняет, что не так. Частые причины:

- IPv6-адрес без квадратных скобок: нужно `[2001:db8::20]:443`, а не `2001:db8::20:443`;
- порт меньше 1 или больше 65535;
- одно и то же правило дважды (тот же протокол и порт);
- порт уже занят другой программой на сервере — освободите его или выберите другой;
- адреса слушания или исходящего адреса нет на сервере;
- исходящий адрес другого типа, чем адрес назначения (IPv4 и IPv6);
- имя у правила `udp` или `both`, имя в неверной форме (IP-адрес, `.example.com`, `example.*`), одно имя
  дважды на порту, два правила без имени на одном порту.

## После установки

1. **Дайте клиентам адрес прокладки** вместо адреса сервера назначения. Порты — те, что слушает прокладка,
   установщик печатает их в конце.
2. **Если сервер назначения пускает не всех**, разрешите на нём адреса прокладки. Установщик тоже печатает их в
   конце.
3. **Если включили PROXY protocol**, проверьте, что сервер назначения его принимает.
4. **Проверьте** с другого компьютера: `nc -vz 192.0.2.10 443` (адрес прокладки и порт). Для UDP эта проверка
   ничего не показывает — проверяйте настоящим клиентом.

## Управление

Команда `nginx-stream` без параметров показывает меню: перенастроить, состояние, удалить, выход.
При перенастройке прошлые ответы подставляются сами — достаточно поменять нужное.

```bash
nginx-stream               # меню
nginx-stream --status      # состояние: работает ли nginx, какие порты, сколько соединений
nginx-stream --uninstall   # удалить прокладку
```

Пример `--status`:

```
nginx: active
Порты:
  tcp 443 -> [2001:db8::10]:443  [up, 12 conn]
  udp 8443 -> [2001:db8::10]:443  [up]
UDP-сокетов nginx: 2
Таблица защит nft: есть
Служба портов: active, правил открыто: 2
```

**Удаление** возвращает сервер как было: снимает правила фаервола, которые добавил установщик, возвращает
прежние настройки nginx и ядра (ядро — после перезагрузки). Пакет nginx удаляется, только если вы согласитесь;
если nginx обслуживает и сайты, он остаётся. Подробности — в [docs/details.md](docs/details.md#удаление).

## Все параметры

Любой ответ можно передать флагом. С `--yes` установщик ничего не спрашивает и берёт значения по умолчанию для
всего, что не задано. Так удобно ставить скриптом или на много серверов.

```bash
bash install.sh --yes --target 2001:db8::10 --ports 'tcp:443,udp:443'
```

**Значение `--ports` пишите в одинарных кавычках**: без них знак `>` командная строка примет за перенаправление.

| Флаг | Что задаёт | Значения | По умолчанию |
|---|---|---|---|
| `--lang` | язык | `ru`, `en` | спросит; с `--yes` — `ru` |
| `--target` | адрес сервера назначения | IPv4, IPv6 (можно без скобок), домен | — |
| `--ports` | правила портов | см. «Правила портов» | `tcp:443` |
| `--listen` | на каких адресах слушать | `v4` — только IPv4, `v4v6` — IPv4 и IPv6 | `v4v6`, если есть IPv6 |
| `--proxy-protocol` | передавать адрес клиента | `y` / `n` | `n` |
| `--logs` | журнал nginx | `off` — нет, `error` — только ошибки | `off` |
| `--tcp-timeout` | через сколько закрыть TCP, по которому ничего не идёт | `90s` (секунды), `10m` (минуты), `1h` (часы), `1d` (дни) | `10m` |
| `--udp-timeout` | то же для UDP | так же | `10m` |
| `--tune` | параметры ядра | `y` / `n` | `y` |
| `--ssh-protect` | защита SSH от перебора | `y` / `n` | `y` |
| `--scan-protect` | защита от сканирования | `y` / `n` | `n` |
| `--auto-updates` | автообновления безопасности | `y` / `n` | `y` |
| `--yes` | не задавать вопросов | | |
| `--status` | показать состояние | | |
| `--uninstall` | удалить прокладку | | |
| `--dry-run` | только собрать файлы настроек в папку, ничего не ставить; root не нужен | | |
| `--out` | папка для `--dry-run` | путь | `./out` |
| `--ram-mb` | объём памяти для расчёта параметров ядра, только с `--dry-run` | число МБ | `1024` |
| `--help` | краткая справка | | |

`--target` можно не задавать, только если у каждого правила указан свой адрес назначения (это работает
только с флагами, в вопросах адрес обязателен).

Цветной вывод отключается переменной `NO_COLOR=1`.

Примеры:

```bash
# Самый простой случай: TCP 443 на сервер, доступный по IPv6
bash install.sh --yes --target 2001:db8::10

# TCP и UDP 443, плюс UDP 8443 на 443
bash install.sh --yes --target 203.0.113.10 --ports 'both:443,udp:8443>443'

# Несколько серверов; сервер по умолчанию задан доменом; слушать только IPv4
bash install.sh --yes --target backend.example.com \
  --ports 'tcp:443,tcp:2222>203.0.113.20:22,udp:51820>[2001:db8::20]:51820' --listen v4

# Два внешних адреса прокладки — два сервера назначения
bash install.sh --yes --ports 'udp:192.0.2.20:443>[2001:db8::20]:443,udp:192.0.2.21:443>[2001:db8::21]:443'

# Порт 443 по именам сайтов, остальное и UDP — на сервер по умолчанию
bash install.sh --yes --target 203.0.113.9 \
  --ports 'tcp:443/a.example.com>[2001:db8::10]:443,tcp:443/*.b.example.com>203.0.113.5:443,tcp:443>203.0.113.9:443,udp:443'
```

Посмотреть, какие файлы будут записаны, ничего не устанавливая (можно и на своём компьютере):

```bash
bash install.sh --dry-run --yes --target 2001:db8::10 --out ./out
```

Готовые результаты для разных случаев — в [examples/](examples/).

## Частые проблемы

**Клиенты не подключаются.** Проверьте по порядку:
1. `nginx-stream --status` — nginx `active`, нужный порт `up`;
2. порт открыт у хостинга: у многих провайдеров есть свой фаервол в панели управления — откройте там порты
   прокладки;
3. сервер назначения доступен с прокладки: `nc -vz 2001:db8::10 443` (на самой прокладке);
4. сервер назначения пускает адреса прокладки (см. «После установки»).

**«Порт уже занят».** На сервере этот порт слушает другая программа. Посмотреть какая:
`ss -lntup | grep :443`. Остановите её или выберите другой порт.

**«Нет IPv6».** Сервер назначения доступен по IPv6, а у прокладки IPv6 нет. Включите IPv6 в панели хостинга
или возьмите другой сервер.

**Сменился IP у домена назначения.** nginx узнаёт IP домена только при запуске: `systemctl restart nginx`.

**Включили ufw после установки.** Запустите `nginx-stream`, выберите «перенастроить» и оставьте те же ответы —
порты откроются и в ufw.

**Стоит firewalld.** Установщик в него ничего не добавляет и печатает порты — откройте их в firewalld сами.

**На сервере уже есть сайты на nginx.** Ничего не сломается: установщик добавит прокладку к ним одной строкой и
не будет переписывать их настройки. Порт, который занят сайтом, прокладке отдать нельзя — выберите другой.

## Подробности

Как всё устроено внутри — какие файлы меняются, как работает фаервол, почему выбраны те или иные настройки, чем
это отличается от iptables DNAT — в [docs/details.md](docs/details.md).
