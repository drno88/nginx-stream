# nginx-stream: как устроено

Справка для тех, кто хочет знать, что именно установщик делает с сервером. Как поставить и заполнить
параметры — в [README](../README.md).

## Чем отличается от iptables DNAT

DNAT делает ту же работу в ядре и для многих задач подходит лучше. nginx-stream нужен там, где DNAT не справляется:

| | iptables DNAT | nginx-stream |
|---|---|---|
| IPv4 на входе, IPv6 на выходе | нет | да |
| Шифрованный поток | насквозь | насквозь, сертов и ключей на прокладке нет |
| Выбор сервера по имени в TLS | нет | да |
| Чужие правила и IPv6 на сервере | зависит от того, как настроено | не трогаются |
| Накладные расходы | минимальные, всё в ядре | выше: данные проходят через процесс nginx |
| IPv4 на IPv4 | проще и быстрее | работает, но DNAT для этого достаточно |

Если и вход, и сервер назначения — IPv4 и нужна максимальная скорость на слабом сервере, DNAT лучше. Если нужен
переход IPv4 → IPv6, разные хосты по правилам или не хочется менять правила iptables, берите nginx-stream.

## Правила портов: точная семантика

```
proto:[listen_ip:]listen[/name][>[host:]port][@src]
```

- `proto` — `tcp`, `udp` или `both` (то же, что два правила: tcp и udp).
- `listen_ip` — адрес прокладки, на котором слушать, IPv4 или IPv6 в квадратных скобках. Адрес должен быть на
  сервере (`ip addr`), IPv6 пишите так же, как его показывает `ip addr`. Без него правило слушает все адреса
  (вопрос «На каких адресах слушать?»).
- `listen` — порт на прокладке, 1–65535; ведущие нули отбрасываются.
- `/name` — только `tcp`: имя из TLS ClientHello (SNI). Точное имя или `*.zone` (все поддомены, сама зона не
  входит); регистр не важен, punycode допускается, до 253 символов. Правила с одним адресом слушания и портом —
  группа: любое число правил с именами и не больше одного без имени. Без имени, с чужим именем и не TLS —
  правило без имени; если его нет — цель первого правила с именем (с его `@src`). Имя проверяется только по
  синтаксису, в DNS установщик не ходит. Правило без адреса слушания пересекается с любым правилом на том же
  протоколе и порту, поэтому именованная группа на `*:443` и `tcp:192.0.2.1:443` вместе не допускаются.
- после `>` — порт на сервере назначения, по умолчанию тот же; перед портом — свой хост: IPv4, IPv6 в
  квадратных скобках или домен. По умолчанию берётся `--target`.
- `@src` — адрес прокладки, с которого она ходит к серверу назначения (`proxy_bind`), IPv4 или IPv6 в скобках.
  Должен быть на сервере и того же семейства, что адрес назначения; если назначение — домен, он должен
  резолвиться в адреса того же семейства. Без `@src` адрес выбирает ядро по маршруту.

## Что меняется на сервере

| Файл | Для чего |
|---|---|
| `/etc/nginx/nginx.conf` | главный конфиг (только в режиме «свой nginx»); прежний сохраняется как `nginx.conf.before-nginx-stream`; на время установки каждый заменяемый файл копируется рядом как `<файл>.nginx-stream-bak` (при успехе копии удаляются) |
| `/etc/nginx/nginx-stream.conf` | блок `stream`: upstream и server на каждую пару (протокол, хост цели, порт цели); на порт с именами — один server и map по имени в TLS |
| `/etc/systemd/system/nginx.service.d/nginx-stream.conf` | `LimitNOFILE=262144`, `Restart=on-failure`, `RestartSec=2s` |
| `/etc/sysctl.d/90-nginx-stream.conf` | параметры ядра (при тюнинге); значения зависят от объёма памяти |
| `/etc/modules-load.d/nginx-stream.conf` | загрузка `tcp_bbr` (если BBR доступен) |
| `/etc/nginx-stream/firewall.nft` и служба `nginx-stream-firewall.service` | защита SSH и/или от сканирования, в своей таблице `inet nginx_stream` |
| `/etc/nginx-stream/ports.sh` и служба `nginx-stream-ports.service` | открытие портов прокладки в фаерволе сервера (см. «Фаервол»): скрипт `up`/`down` со списком портов и юнит, который запускает его при загрузке и вместе с чужим фаерволом |
| `/etc/systemd/system/nftables.service.d/nginx-stream.conf` | после каждого старта `nftables.service` (его `flush ruleset` стирает наши правила) перезапускает службы защит и портов |
| `/etc/nginx-stream/settings.env` | все ответы установщика, режим nginx, список правил ufw |
| `/usr/local/sbin/nginx-stream` | копия установщика для повторного запуска |
| правила ufw | `ufw allow <порт>/<proto> comment nginx-stream`, если ufw активен (при выключенном ufw правила не меняются, записанные раньше остаются в `settings.env`); при firewalld порты только печатаются |
| правила iptables и nftables | `ACCEPT` на порты прокладки с пометкой `nginx-stream`, если входящие фильтруются; ставит и снимает служба `nginx-stream-ports` |

Пакеты (ставятся только недостающие; `libnginx-mod-stream` не нужен, если nginx уже стоит со встроенным
stream, как в сборке nginx.org): `nginx`, `libnginx-mod-stream`, при включённых защитах — `nftables`, при
автообновлениях — `unattended-upgrades`. `dist-upgrade` не выполняется. Если все пакеты уже стоят
(перенастройка), apt не вызывается. На свежей ВМ первым делом может работать cloud-init, а затем первое
автообновление: установщик дожидается cloud-init (до 10 минут), потом освобождения apt (тоже до 10 минут, раз в
минуту сообщает, что ещё ждёт). Свежий nginx при установке пакета не запускается со стоковым сайтом — только с
готовой конфигурацией прокладки.

Если nginx не запустился с новой конфигурацией, установщик возвращает прежние файлы и перезапускает nginx с ними.
Прерывание (Ctrl+C, обрыв SSH) во время установки тоже откатывает изменения.

## Фаервол

- ufw установщик не ставит. Если ufw активен, порты прокладки открываются в нём (`ufw allow ... comment
  nginx-stream`). Включили ufw уже после установки — запустите `nginx-stream` и перенастройте с теми же ответами.
- Остальные фаерволы ведёт служба `nginx-stream-ports`. Она ставится всегда и при каждом запуске заново решает,
  где открыть порты `listen`:
  - iptables/ip6tables — если ufw не активен (иначе наш `ACCEPT` обошёл бы запреты в ufw): `ACCEPT` с комментарием
    `nginx-stream` вставляется перед последним сплошным `-j DROP`/`-j REJECT` цепочки `INPUT` (допускаются
    комментарий и `-i интерфейс`), а если такого нет и политика DROP — в конец; `iptables` — для IPv4,
    `ip6tables` — для IPv6-слушания. Не первым правилом: оно обошло бы чужие баны вроде `-s X -j DROP` и наборы
    блокировок;
  - nftables — в каждой чужой базовой цепочке `type filter hook input` (кроме нашей `inet nginx_stream` и
    цепочки `INPUT` таблиц iptables-nft): `accept` с `comment "nginx-stream"` вставляется перед последним
    правилом, которое сплошное `drop`/`reject` (допускаются `counter`, `log`, `comment` и `iifname`), а если
    такого нет и `policy drop` — в конец: в таблицу `ip` — порты IPv4, в `ip6` — IPv6, в `inet` — все. Цепочка с
    `policy accept` и финальным `reject` тоже открывается.

  Если цепочка пропускает по умолчанию и сплошного запрета в конце нет (частичные баны — дело владельца), порты в
  ней и так открыты, и ничего не вставляется; если при этом во входящих есть DROP/REJECT, установщик
  предупреждает — проверьте порты. Перед вставкой служба снимает свои помеченные правила, дублей нет.
  Политики и чужие правила не меняются. Все вызовы `iptables` идут с `-w 5` (ждут xtables-lock при загрузке
  вместе с docker и fail2ban). `netfilter-persistent save` не используется: он сохранил бы весь текущий набор,
  включая динамические цепочки docker.
- Обе службы — защит (`nginx-stream-firewall`) и портов — стартуют после `nftables.service` и
  `netfilter-persistent` и следуют за ними: после restart, reload и stop+start наша таблица и правила
  возвращаются. Первый `systemctl start nftables` (фаервол включили уже после установки) уже запущенные службы
  сам не перезапускает — это делает drop-in `/etc/systemd/system/nftables.service.d/nginx-stream.conf`
  (`ExecStartPost`). Ручной `nft -f /etc/nftables.conf` (мимо systemctl) стирает нашу таблицу и правила до
  `systemctl restart nginx-stream-firewall nginx-stream-ports`; `--status` показывает, есть ли таблица и сколько
  правил открыто.
- При перенастройке скрипт переписывается. `--uninstall` снимает наши правила, удаляет службы и drop-in и
  убирает строки с пометкой `nginx-stream` из `/etc/iptables/rules.v4|v6` и `/etc/nftables.conf`, если они там есть.
- firewalld: если он активен, служба ничего не вставляет (его reload стёр бы наши правила), порты только
  печатаются — откройте их сами.

## Два режима nginx

- **Свой.** На nginx больше ничего нет: `nginx.conf` и сайт `default` совпадают с пакетными (по контрольным
  суммам dpkg), других сайтов нет, `conf.d` пуст, в `/var/www/html` нет ничего, кроме страницы пакета (стоковый
  сайт `default` отдаёт именно этот каталог). Установщик пишет свой `nginx.conf` и убирает сайт `default`,
  чтобы освободить порт 80 для правила. В любом сомнительном случае выбирается общий режим.
- **Общий.** nginx уже обслуживает сайты. `nginx.conf` не переписывается: в него добавляется одна строка
  `include /etc/nginx/nginx-stream.conf;` после `include /etc/nginx/modules-enabled/*.conf;` (если такой
  строки нет — в конец файла: перед строками `load_module` include сломал бы `nginx -t`). Закомментированный
  `#include ...` за include не считается. Если в конфигурации уже есть блок `stream {`, установщик
  останавливается: второй блок `stream` nginx не принимает. Если режим был «свой», но `nginx.conf` после
  установки изменили, при перенастройке выбирается «общий». Лимиты воркеров в этом режиме не меняются; если
  соединений много, поднимите `worker_rlimit_nofile` и `worker_connections` сами.

## Удаление

`--uninstall`:

- останавливает и удаляет службу защит и таблицу `inet nginx_stream`, службу портов `nginx-stream-ports` и
  drop-in для `nftables.service`;
- удаляет файлы sysctl и modules-load; **значения ядра остаются до перезагрузки**;
- удаляет override systemd и `/etc/nginx/nginx-stream.conf`;
- в режиме «свой» возвращает прежний `nginx.conf` и сайт `default`; в режиме «общий» убирает строку include;
- удаляет правила ufw, iptables и nftables, которые добавил установщик (правила, бывшие до него, не трогает);
  правила ufw снимаются, если ufw установлен, даже выключенный;
- в режиме «свой» спрашивает, удалять ли пакет nginx (по умолчанию нет); в режиме «общий» не спрашивает и
  оставляет nginx — он обслуживает и другие сайты, а удаление пакета снесло бы `/etc/nginx` вместе с ними;
  если nginx остаётся, проверяет конфигурацию и перезапускает его, а если его поставил сам установщик (до
  установки nginx не было) — останавливает и выключает (`systemctl disable --now nginx`). Без терминала и без
  `--yes` на вопрос о пакете отвечается «нет»;
- удаляет `/etc/nginx-stream` и `/usr/local/sbin/nginx-stream`.

Пакеты `nftables` и `unattended-upgrades` остаются, как и автообновления
(`/etc/apt/apt.conf.d/20auto-upgrades`). Если согласиться удалить nginx, удаляются `nginx`, `nginx-core`,
`nginx-common`, `libnginx-mod-stream` (purge удаляет весь `/etc/nginx`); ставшие ненужными зависимости не
трогаются — убрать их можно вручную: `apt autoremove`.

## Тонкости

Коротко, почему сделано так.

- `worker_shutdown_timeout 10s` — только если есть UDP-правило. Клиенты UDP шлют keepalive, и после reload старые
  воркеры держали бы свои сессии бесконечно. При смешанных правилах (TCP и UDP) TCP-соединения старых воркеров
  рвутся через 10 с после reload; установщик применяет конфиг перезапуском (`restart`), так что это касается только
  ручного reload. Для набора только из TCP-правил параметра нет.
- Порт с именами. Имя берётся из TLS ClientHello (`ssl_preread`), расшифровки нет. Без имени, с чужим именем и не
  TLS — на цель по умолчанию. Если имя скрыто (ECH), виден только внешний SNI. Работают только протоколы, где
  первым говорит клиент; если клиент молчит, nginx через 30 с (`preread_timeout`) закрывает соединение — такие
  службы держите на отдельном порту. Нужен модуль `stream_ssl_preread` (в пакетах Debian и Ubuntu он есть);
  без него установщик остановится.
- Сайт этого же nginx на 443 вместе с разбором по имени не живёт: перенесите сайт на другой порт и дайте правило
  `tcp:443/site.example.com>127.0.0.1:8443`.
- Значения map — имена upstream, а не `host:port`: домен в переменной потребовал бы `resolver`. Исходящий адрес
  для имён — отдельный map, пустое значение означает «без привязки». `map_hash_bucket_size` — 128, при именах
  длиннее ~110 символов — 512.
- `reuseport` на UDP. Без него датаграммы одного клиента разбирают разные воркеры, у каждого свой исходящий
  сокет, и сервер видит обрывки разных сессий.
- `max_fails=0`. Если домен даёт и IPv4, и IPv6, то после секундного сбоя одного адреса nginx выключил бы его
  на `fail_timeout` и увёл бы всех на другой. Сорвавшееся соединение клиент повторит сам.
- `restart`, а не `reload`. Новые лимиты и сокеты `reuseport` применяются только при перезапуске.
- `sysctl -e -p <файл>`, а не `sysctl --system`. В `/etc/sysctl.d/` на чужом сервере может лежать, например,
  `disable_ipv6=1`; применяется только наш файл. Исходящие порты — 10000–65535; в `ip_local_reserved_ports`
  попадают порты прокладки от 10000 и TCP-порты от 10000, которые слушались на момент установки, — чтобы
  исходящие соединения nginx их не заняли.
- `nftables.service` не включается. Его `/etc/nftables.conf` начинается с `flush ruleset` и снёс бы правила
  docker и ufw. Вместо этого своя служба загружает только таблицу `inet nginx_stream`; если фаервол сервера
  включён через `nftables.service` (до установки или после), наша таблица возвращается после каждого его старта.
- Домен назначения nginx резолвит только при старте. Если домен даёт и A, и AAAA, в upstream попадают оба адреса.
- `proxy_buffer_size 64k`. Значение по умолчанию (16k) даёт лишние системные вызовы на толстом потоке.
- Защита от сканирования не трогает RST от nginx (с портов `listen` и эфемерных 10000–65535), SSH и всех
  TCP-портов, которые слушались на момент установки. Иначе соединения, оборванные nginx или другой службой,
  висели бы у собеседника до тайм-аута.
- Защита SSH считает пакеты SYN на всех портах sshd, а не состояние соединения: правило с `ct state` включило бы
  conntrack на весь трафик прокладки, и на сервере с малой памятью таблица переполнялась бы под нагрузкой.
  Сеть — /24 для IPv4 и /64 для IPv6, счётчики живут 2 минуты.
- `proxy_bind`, а не SNAT. SNAT требует conntrack и правил в таблице nat и пересекается с ufw и docker;
  `proxy_bind` делает сам nginx, по правилу, и ничего не добавляет в ядро.
- BBR включается, только если модуль `tcp_bbr` загружается и `bbr` есть в доступных алгоритмах.
- Вывод цветной, только если идёт в терминал; цвет отключают `NO_COLOR` (любое непустое значение) и `TERM=dumb`.

## Примеры

[examples/](../examples/) — результат `--dry-run` для типичных случаев; параметры каждого — в его `settings.env`.

- `tcp-443` — один порт: TCP 443 на сервер назначения по IPv6;
- `tcp-udp` — TCP и UDP 443 плюс UDP 8443 → 443 на один сервер назначения;
- `multi-target` — три правила на три разных сервера назначения, с защитой SSH и от сканирования;
- `multi-ip` — правила на разных адресах слушания прокладки (IPv4 и IPv6) к разным серверам назначения, с
  исходящими адресами прокладки (`@src`) у двух правил;
- `sni` — разбор по имени на TCP 443 (три цели, включая цель по умолчанию, `@src` у одной из них) плюс UDP 443 на
  сервер по умолчанию.
